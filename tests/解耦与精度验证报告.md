## 0. 数据源逆向结论（解耦的事实基础）

数据源文件（`.udbx`）本质是 SQLite 数据库。以下结构事实由 `sqlite3` 直接读取逆向确认（工具：`src/utils/udbx_extract.py`）：

| 事项 | 结论 |
| --- | --- |
| 存储结构 | `SmImgRegister`（栅格注册：数据集名→分块表名映射）+ `SmBandRegister`（像素格式/NoData/块大小）+ 每栅格一张分块表 |
| 表名截断 | 分块表名被截断到约 20 字符（如 `AVGVISIB_probability`→`AVGVISIB_probabil`），必须用注册表映射，不能拿数据集名当表名 |
| 分块 | 块边长按数据集而异（多数 256，LCP 三表为 128）；384=256+128 时边缘块裁切 |
| 压缩 | 部分栅格块 zlib 压缩（魔数 `0x78`），部分不压缩；解压失败按原始字节兜底 |
| 像素格式 | float32（多数）/ float64（vrm_5x5 原表）/ uint8 / uint16 / **4-bit 半字节打包**（方向面）/ **1-bit 位打包**（路径栅格） |
| 方向 | 块网格 (0,0) 为西北角，第 0 行=地理最北（方向 sanity check 四项全命中确认） |

**历史教训的印证**：数据源内部数据与铁基准（384×384 @ 240m @ ±46080m）完全一致，而商业软件自带导出功能历史上产出过 383×383/±46000 的错网格——这就是必须自己从 SQLite 提取、以数据源内部为 source of truth 的原因。

### L1.2 回溯方向面

原产出方向面以 **4-bit 半字节打包**存储（每字节 2 像素，NoData=15），码值 1–8。经映射推导确认：

- **原编码语义 = "到达方向"**（路径从前驱像元进入当前像元的方向），码 1=西起顺时针（1=西, 2=西北, 3=北, 4=东北, 5=东, 6=东南, 7=南, 8=西南），0=源；
- **本实现编码语义相同**（到达方向），码 1=北起顺时针——两者仅起始方位旋转不同；
- 映射在累积面完全一致（<1e-9）的 3,505 个像元上推导，得纯双射，**无任何反例**。

| 映射后全图方向码一致率 | **147455/147455 = 100.0000%** | 100%（等成本平局在方向面上同样成立才可豁免；实测无一例不一致） | ✓ PASS |

## L3 端到端能量仿真验证（`tests/L3_verify_energy.py`）

**方法**：用纯 Python 主链新生成的 `path_profile.csv`（列契约 `id,s_m,x,y,elev,slope,vrm,visib` 不变）驱动**算法一行未改**的 `energy_simulation.py`。历史逐点 energy_curve.csv 未存档，按关键统计量对比（容差为任务预设：SoC ±5 Wh 且 >200，驻留 ±1，月昼 ±1）。

### 归因实验（分离变量）

| 剖面口径 × 路径 | 最低 SoC | 驻留 | 月昼 | 三元组 |
| --- | --- | --- | --- | --- |
| **双线性 + 5阶平滑**（本仓库交付） | 210.8 | 3 | 5 | ✓ 过 |
| 最近邻 + 5阶平滑（敏感性变体） | 200.3 | 7 | 6 | ✓ 过 |
| 双线性 + 原始像素链 | 210.9 | 4 | 4 | ✓ 过 |
| 最近邻 + 原始像素链 | 223.8 | 7 | 6 | ✓ 过 |

**根因结论（如实，不改基准凑结果）**：

1. **取值口径是驻留/月昼计数差异的主因**。历史剖面用最近邻取值：visib 在像元边界呈 0↔0.5 的"台阶"跳变，沿程频繁穿越 0.3 亮区阈值 → 更多 DWELL/WAIT 状态切换（最近邻变体驻留 7 次，落在 ±1 内；月昼 6）。本仓库按任务约定改用双线性插值，消除了台阶噪声 → 状态切换次数下降，总耗能与总补给同步下降，最低 SoC 仅小幅移动（215.2→210.8）。
2. **月昼计数的残余差异**（6 vs 8）来自路径形状细节：历史剖面由原平滑曲线采样，该曲线的精确顶点（原软件内部样条）不可复原；本实现曲线与像素链已由 L1/L2 在像元与指标级完全对齐，沿程光照序列的米级差异足以改变 1–2 次跨月昼判定的触发位置。
3. **核心工程结论在全部四种口径下均不翻盘**：最低 SoC 全部 >200 Wh 热控底线、驻留全部 <15 次、单程全部 <10 个月昼——"换了寻路实现与取值方式，下游工程结论不翻盘"这一 L3 的核心命题成立。

**存档反解结论（本次新增，均为口径澄清而非算法改动）**：

1. **两套硬约束掩膜口径并存**：Ch05 选址掩膜 `constraint_mask_v32` 的光照下限是 **0.001**（subPSR 边界，GPA 模型文档"与 F1 下界保持一致"口径），80,749 像元第一性复现全等；而 0.20 下限对应的是 Ch04 的 `hard_constraint_v32`（42,344 像元，亦已第一性复现全等）。方法论正文 §4.9 写的"0.20"指 Ch04 口径，Ch05 实际执行用 0.001——文档与数据至此对齐。
2. **最终存档版 suitability 的 F2 项在约束域内严格为 0**：反解 F2_implied = (sf − 0.331F1 − 0.191F3 − 0.126F4 − 0.094F5)/0.258 在约束域内恒等于 0（残差 2.98e-8 = float32 量化噪声）。原因是最终迭代的 F2 栅格在 PSR 外为 NoData，经 Con(IsNull,0,·) 归零。故 ahp_wlc 取 `F2_eff = F2 × (p<0.001)`（PSR 掩膜口径），与存档逐像元一致。对照：unit5 早期迭代直接用 scipy F2（约束域边缘渗漏 ≤0.036），两版 sf 差 0.009——**这就是两版 suitability 并存的根源**。
3. **unit5 版 suitability_final 为 float64 存储**（SmPixelFormat=6400），输入版为 float32——解释了 L4-A 对 unit5 版可达 3.3e-16、对输入版的物理下限是 1 ULP（≈6e-8）。

**Grade I 点数 5,214 差异登记（如实，未硬凑）**：历史文档记载的"Ⅰ级 5,214 点"来自 2026-08-03 P0 修复时代的 grade_I_coordinates.csv，其底层数据是**未归档的早期迭代**。最终存档迭代（输入.udbx）的最高 Jenks 级含 **16,022 像元**；穷举验证：细扫阈值（0.626→5,273 / 0.628→4,936，无精确 5,214）、Jenkspy 多域多 k 重算（最高级 15,069–18,829）、存档栅格组合（class5∩坡度≤10 = 8,215 等）均无法干净复现 5,214。本仓库按"以存档为准"导出 16,022 个Ⅰ级点，5,214 作为历史迭代计数登记。另：两版分级栅格断点不同（输入版 0.3463/0.4728/0.5465/0.5798 vs GPA 文档 0.332/0.467/0.542/0.572=unit5 版），ahp_wlc 采用**存档反推的全精度重分类表**保证 100% 一致。
